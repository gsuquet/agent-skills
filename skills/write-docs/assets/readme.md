when it does not apply; keep every other section, in this order.

````markdown

<one sentence: what it does and for whom. A second sentence only when the reason it exists is not obvious: what it replaces or what problem it removes.>

## Quick start

<prerequisites on one line, with versions>

```sh
<the fewest commands from a fresh clone to a first working result>
```

<what the reader sees when it worked>

## Usage

<the 2 to 4 most common tasks, one short command block each; link a how-to for any other task>

## Configuration

<optional: a table `Setting | Default | Effect`, or a link to the reference doc when it has more than 10 rows>

## Development

<optional: the commands to build, test and lint, the same ones CI runs>

## Docs

<optional: links to the docs of this repository, grouped by type: how-to, tutorials, reference, concepts, runbooks, RFCs, ADRs>

## Owners

<who maintains it and where to ask: issue tracker, chat channel>
````
